Expand description

Decodes a Bloom filter from caller-provided file ranges, without performing I/O.

The metadata and pushed bytes must refer to the same file. Ranges use absolute file offsets. Call Self::try_decode to discover which ranges are needed, then supply them using Self::push_range or Self::push_ranges. Bytes may also be pushed in advance to avoid requests for already-buffered data.

Each requested range must be contained in a single pushed buffer; adjacent buffers are not coalesced. After an error from Self::try_decode, discard the decoder.

§Example

use bytes::Bytes;
use parquet::DecodeResult;
use parquet::bloom_filter::{Sbbf, SbbfPushDecoder};
use parquet::errors::Result;
use parquet::file::metadata::ColumnChunkMetaData;

fn decode_filter(metadata: &ColumnChunkMetaData, file_bytes: Bytes) -> Result<Option<Sbbf>> {
    let Some(mut decoder) = SbbfPushDecoder::try_new(metadata)? else {
        return Ok(None);
    };
    loop {
        match decoder.try_decode()? {
            DecodeResult::NeedsData(ranges) => {
                let buffers = ranges.iter().map(|range| {
                    file_bytes.slice(range.start as usize..range.end as usize)
                }).collect();
                decoder.push_ranges(ranges, buffers)?;
            }
            DecodeResult::Data(filter) => return Ok(Some(filter)),
            DecodeResult::Finished => unreachable!("filter was returned above"),
        }
    }
}

let filter = decode_filter(&metadata, file_bytes)?.unwrap();
assert!(filter.check("present"));

pub fn try_decode(&mut self) -> Result<DecodeResult<Sbbf>>

Attempts to decode the filter, returning the file ranges needed if data is missing. Repeated calls before supplying data return the same ranges.

Without prefetched data, requests one range when bloom_filter_length is known, or two otherwise (a 20-byte header estimate, then the bitset). Headers larger than the estimate require an advertised length. After returning DecodeResult::Data, subsequent calls return DecodeResult::Finished.

The state transitions can be visualized as:

                ┌──────────────┐
                │ FindingRange │
                └──────────────┘
                       │
              choose initial range
                       │
                       ▼
             ┌───────────────────┐ ───┐ bytes missing:
             │ ReadingSbbfHeader │    │ return NeedsData(range),
             └───────────────────┘ ◀──┘ wait for push_range(s)
                │               │
           length known   length unknown
                │               │
                │               ▼
                │     ┌───────────────────┐ ───┐ bytes missing:
                │     │ ReadingSbbfBitset │    │ return NeedsData(range),
                │     └───────────────────┘ ◀──┘ wait for push_range(s)
                │               │
                └───────┬───────┘
                        │
                 return Data(Sbbf)
                        │
                        ▼
                  ┌──────────┐ ───┐
                  │ Finished │    │ return Finished
                  └──────────┘ ◀──┘

In the above:

  • The initial range is the whole filter when its length is known, otherwise a 20-byte header prefix.
  • Transitions proceed within the same try_decode() call while the required bytes are buffered; push_range(s) supplies bytes without changing state.
  • Header parsing/validation must succeed before advancing. Any decoding error leaves the decoder unusable.
